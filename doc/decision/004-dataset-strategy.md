# 004: Dataset Strategy (50M)

Status: **Proposed**. One decision needs approval (synthetic data,
see below). Licenses and dataset versions change, so every source
is re-verified against its dataset card when the manifest is built.

## Goals
- About 5B training tokens (see 002) of legally usable text
- Broad coverage: general knowledge, education, science, math, code
- High quality over raw volume
- Every source documented: license, version, date, filters applied

## What a 50M model can and cannot learn
With 5B tokens and 50M parameters the model will learn fluent
language, common facts, basic patterns in math and code. It will
not store large amounts of rare knowledge. Data quality matters
more than coverage: cleaner, more educational text gives more
capability per parameter.

## Proposed mix (5B tokens)

| Domain | Share | Tokens | Example source types |
|---|---|---|---|
| Educational web text | 50% | 2.5B | Quality-filtered, openly licensed web corpora |
| Code | 15% | 0.75B | Permissively licensed repositories (Python, JS first) |
| Math | 8% | 0.4B | Open math web text, proofs, worked solutions |
| Reference / encyclopedic | 10% | 0.5B | Wikipedia, Wikibooks, Q&A sites with open licenses |
| Public-domain books | 7% | 0.35B | Public-domain literature and textbooks |
| Open-access science | 5% | 0.25B | Open-access papers and abstracts |
| Held back | 5% | 0.25B | Reserve for gaps found in evaluation |

Instruction and chat data is not in pretraining. It is added in
post-training (roadmap Phase 8), around 50-100M tokens.

Ratios are a starting point. Phase 6 proof-of-concept runs
will test mix variants on a tiny model.

## Repetition
High-quality sources smaller than their share can be repeated.
Up to about 4 epochs over the same data is generally close to
fresh data in value; beyond that the gain drops quickly. Track
epochs per source in the manifest.

## Licensing and provenance rules
1. Only use data whose license permits training and redistribution
   of the trained weights, or document the exact legal basis.
2. Respect attribution and share-alike terms (e.g. CC BY-SA,
   ODC-By). Keep an attribution list in the repo.
3. For code, permissive licenses only (MIT, Apache-2.0, BSD).
   No GPL/AGPL or unlicensed code.
4. Honor opt-outs and robots/TDM restrictions. No scraping of
   sites that forbid it.
5. Prefer existing curated open datasets over our own scraping.
6. Record in `data/manifest.yaml`: name, URL, version or commit
   hash, license, retrieval date, token count, filters applied.
   Data itself is not committed to the repo.
7. Not legal advice. For public release of weights, review
   licenses of every source.

## Processing pipeline (in order)
1. Collect and record provenance
2. Language ID (English first)
3. Heuristic quality filters (length, symbol ratio, repetition,
   boilerplate)
4. Quality classifier for educational value (a small classifier
   we train ourselves is acceptable; if pre-filtered public
   subsets are used, record how their filtering was made)
5. Exact deduplication (hash)
6. Near-duplicate removal (MinHash LSH)
7. PII scrubbing: emails, phone numbers, IP addresses, API keys,
   credentials
8. Safety filtering: explicit and abusive content, with the
   thresholds documented
9. Decontamination against every evaluation set (13-gram overlap)
10. Split train/validation by document hash
11. Tokenize, pack to 2048, write ~100M-token shards (uint16)

Dedup runs before the split so validation does not leak from train.

## Validation
- Fixed held-out set of about 10M tokens, never trained on
- Per-domain slices (web, code, math, books) so we see which
  domains improve
- A frozen copy, versioned with the dataset version

## Contamination
Benchmarks chosen in the evaluation doc (005) are added to a
blocklist before any training. If contamination is found after the
fact, the result is flagged, not silently dropped.

## Synthetic data: decision needed

Synthetic text generated by other LLMs is popular for small models,
but it raises provenance and terms-of-use questions, and it
blurs the "from scratch" story.

| Option | Description | Verdict |
|---|---|---|
| A | Human-written and openly licensed data only | **Recommended for 50M** |
| B | Allow synthetic corpora made by open-weight LLMs | Revisit at 100M as an ablation |
| C | Synthetic data from our own trained model | Later research |

Never use data generated by closed LLM APIs. Many instruction
datasets are built this way and may violate those services' terms.

## Practical constraints
- Download and process on Kaggle/Colab by streaming, not on the
  laptop, to avoid bandwidth and disk limits
- Keep tokenized shards on a persistent store (Hub or Kaggle
  Dataset) so any session can resume
- Check free-tier storage limits before each stage

## Open questions
- Exact sources per domain (selected when building the manifest)
- Code share vs Python/JS emphasis
- English-only or some multilingual share
- Whether quality-filter strength costs too much diversity
